# Implementation Contract

The service binds to `127.0.0.1:4173` by default. All endpoints below are prefixed `/api` and return JSON. Errors are `{ "error": "message" }` with a non-2xx status. No tokens in API responses. Types live in `src/shared.ts`.

## Endpoints

- `GET /workspaces`: `WorkspaceList` (`workspaces`, `defaultWorkspaceId: string | null`, `limit`). An empty registry returns `workspaces: []` and `defaultWorkspaceId: null`.
- `GET /workspaces/repositories?credential=dedicated|github`: `WorkspaceRepositories` (`login`, `repositories: {id, fullName, defaultBranch}[]`). Unscoped, read-only server-authenticated GitHub discovery; omitted credential defaults to dedicated. Uses the same startup-resolved credential as sync, never browser credentials or automatic fallback. Lists only private repositories owned by that authenticated user and visible to the token, excluding organization/collaborator repositories. Fetches `/user` and locally constructed `/user/repos` pages (100 per page, at most 10 pages, 15-second overall timeout); rejects redirects and incomplete results at the page limit, never follows remote links. Missing credentials return 503, invalid query fields/modes return 400, sanitized upstream failures return 502. Returns no tokens or raw GitHub payloads and uses `Cache-Control: no-store`, with the same local Host/Origin protection as other management APIs. This is not a multi-user authentication endpoint.
- `POST /workspaces`: `CreateWorkspaceInput` -> `Workspace`, status 201. The first workspace created in an empty registry becomes the default.
- `GET /workspaces/branches?credential=dedicated|github&repo=OWNER/REPO`: `WorkspaceBranches` (`branches: string[]`). Explicit credential and repo required. Verifies `/user` against private repository metadata and user ownership before listing actual `/repos/{owner}/{repo}/branches` pages (100 per page, at most 10 pages; incomplete results fail). Only sync-supported branch names are returned; no default is auto-selected.
- `GET /workspaces/files?credential=dedicated|github&repo=OWNER/REPO&branch=BRANCH`: `WorkspaceFiles` (`paths: string[]`). All query fields required. Repeats private ownership verification, resolves an actual branch through an encoded branch endpoint, then recursively lists its commit's Git tree. Rejects truncated/malformed trees, more than 100,000 tree entries or 2,000 JSON candidates. Returns only safe regular JSON file paths, not symlinks, contents, or verified portable states. New safe paths remain valid configuration targets for publishing local state; sync preview verifies contents/availability.

Branch/file discovery is unscoped, read-only, server-authenticated and no-store, with the same Host/Origin protections and credential boundaries as repository discovery. Unsupported/duplicate query fields and unsafe targets return 400; missing selected credentials return 503; sanitized upstream failures return 502. Each operation has a 15-second overall timeout, fixed locally constructed GitHub API URLs, encoded refs, redirect rejection, and no remote Link following or raw payload/token exposure. UI selection progresses repository -> explicitly selected branch -> existing/new path, resetting downstream values on edits and all values on credential changes. Discovery never changes persistent workspace state.

- `PATCH /workspaces/:id`: `UpdateWorkspaceInput` -> `Workspace`. Rename or local-to-cloud connection only; reject cloud retargeting and cloud-to-local demotion.
- `GET /workspaces/:id/removal-preview`: `WorkspaceRemovalPreview` with workspace metadata, task/dependency/reference counts, local dirty status, `canRemove`, blocking `reason`, and a revision fingerprint. No remote requests.
- `DELETE /workspaces/:id?confirm=true`: `{revision: string}` -> updated `WorkspaceList`. Requires explicit confirmation and a current removal preview. Stale previews and active state sync return 409. The final workspace can be removed. Removes only local registration, SQLite graph, layouts, sync bookkeeping, and backups; never writes to GitHub. Stops local runtime services before deleting database files. Failed file cleanup is retained durably and retried on startup. Run only one server against a data directory; multiple active in-process managers block removal.

Workspace management is always unscoped. Every existing endpoint below also accepts `/workspaces/:id` after `/api`. Unscoped domain endpoints use the persisted default workspace and return 404 when no workspace exists; workspace management and health remain accessible. Explicit unknown or removed IDs fail without fallback. The existing SQLite database initially remains workspace `default`; new IDs are server-generated. Zero to three entries are allowed. Removing the default assigns the oldest surviving workspace as default without changing its identity, or sets `defaultWorkspaceId` to null when none survive. An empty registry stays empty on startup; removed workspaces are not recreated. Legacy environment conversion applies only to the original `default` if it still exists. The empty UI offers **Add/connect workspace**. Workspaces isolate local graphs and sync bookkeeping. Browser tabs select independently via `?workspace=ID`; selection does not change the CLI/server default. CLI `--workspace ID` overrides process `FOGGY_WORKSPACE`; with neither it keeps legacy paths.

- `GET /state`: `Snapshot` with computed task states.
- `POST /tasks`: `CreateTaskInput` -> `TaskView`, status 201.
- `PATCH /tasks/:id`: `UpdateTaskInput` -> `TaskView`.
- `POST /tasks/:id/done`: `{done: boolean}` -> `TaskView`. Manual steps only.
- `GET /tasks/:id/deletion-preview`: `DeletionPreview`.
- `DELETE /tasks/:id?confirm=true`: `{deleted: string[]}`. Reject without confirmation.
- `POST /dependencies`: `{prerequisiteId, dependentId}` -> `Dependency`, status 201.
- `DELETE /dependencies/:id`: `{ok: true}`.
- `POST /references`: `{containerId, taskId}` -> `TaskReference`, status 201.
- `DELETE /references/:id`: `{ok: true}`. Unlinks without deleting the target.
- `PUT /layout`: `Layout` -> `Layout`. `viewId` is a container ID or `root`.
- `GET /github/status`: `GithubStatus`.
- `GET /github/prs`: `GithubPr[]`. Authored open PRs, cached by polling.
- `POST /github/sync`: `GithubStatus`. Fetch immediately; report errors in status.
- `GET /sync/status`: `SyncStatus`. Local workspace sync configuration and baseline status; no remote request.
- `POST /sync/preview`: `{resolution?: "local" | "remote"}` -> `SyncPreview`. Read-only three-way merge preview. Resolution chooses only conflicting values; `canApply`, `conflicts`, and `validationError` must be inspected. Change lists describe proposed changes to each side, not changes since the baseline.
- `POST /sync/apply`: `{previewId: string, confirm: true}` -> `SyncStatus`. Requires a reviewed, applicable, single-use preview. Reject stale local/remote state with 409; never creates a preview or retries a remote write. Re-preview after failures/timeouts because an upload may have committed.

## Core API

`src/core.ts` exports `Store` and `DomainError`. Constructor: `new Store(databasePath: string)` (supports `:memory:`). Methods: `snapshot()`, `createTask(input)`, `updateTask(id,input)`, `setDone(id,done)`, `addDependency(prerequisiteId,dependentId)`, `removeDependency(id)`, `addReference(containerId,taskId)`, `removeReference(id)`, `previewDeletion(id)`, `deleteTask(id)`, `saveLayout(layout)`, `updatePr(id, {state?, checkedAt, error})`, `close()`. `DomainError` exposes `status: number`.

Input validation is required at runtime. A task's own condition is manualDone, PR merged, or all owned + referenced children completed. Empty containers are not complete. A task completes only if its own condition and all prerequisite tasks are complete. An early satisfied condition is ready; incomplete own condition is available or blocked. All completion is derived, so reopening propagates. WaitingOn is incomplete direct prerequisites. Containers may be nested. References add an existing independently owned task as a child; references are not copies. Duplicate membership and all effective cycles (containment + references + dependencies) are rejected. Deleting a task deletes owned descendants, never reference targets, removes touching dependencies/references, and recalculates. Preview includes externally affected tasks, transitively, including parent containers.

GitHub URLs: HTTPS github.com/{owner}/{repo}/pull/{number} only, normalized. PR URL changes reset verified state. Poll errors retain last verified state but set error. Pollers must not apply a response for a URL that has changed in the meantime.

## Workspace Sync

Legacy `FOGGY_SYNC_REPO`, `FOGGY_SYNC_BRANCH`, and `FOGGY_SYNC_PATH` initialize the default workspace as cloud, or convert an existing local default on restart while preserving its name and SQLite data. Once the default is cloud, its persisted target and credential take precedence; changing or removing legacy variables does not retarget or demote it. Legacy conversion uses dedicated credentials and performs no remote requests. A missing `FOGGY_SYNC_TOKEN` does not prevent startup or local data access; sync preview/apply fail with a credential error. Malformed supplied tokens and invalid legacy targets remain configuration errors.

`Workspace` has `{id, name, type: "local" | "cloud", target: SyncTarget | null, credential: "dedicated" | "github" | null}`. Local workspaces have null target/credential. Cloud workspaces remain local-first SQLite graphs, not hosted databases. Create/connect save configuration without remote reads or writes; use sync preview/apply to fetch existing remote state or publish local state. Cloud defaults are branch `main`, path `foggybrain/state.json`, and credential `dedicated`.

`src/sync.ts` owns manual workspace sync, separate from PR polling. Only a configured private repository and existing branch are accepted. Dedicated mode uses only server `FOGGY_SYNC_TOKEN`; explicit `credential: "github"` opts into reuse of server `GH_TOKEN`, `GITHUB_TOKEN`, or `gh auth token`. Either mode requires Contents read/write on the selected private state repository; dedicated mode never automatically falls back to GitHub credentials. GitHub Contents API writes use the reviewed file SHA. Portable state is versioned JSON (`PortableState`), preserving task/relationship IDs but excluding layouts, timestamps, derived completion, and PR verification. The Store validates imported fields and the entire merged graph using the existing completion/cycle algorithm. Existing local PR verification is retained only for matching identities and URLs; imported PRs must be verified locally.

SQLite retains a per-target common baseline and pending upload intent across restarts. The server retains only one process-local preview, replaced on re-preview and consumed on apply. Two nonempty sides without a baseline cannot be automatically reconciled. Concurrent local edits during upload are preserved and remain unsynced; uncertain remote outcomes require a new preview and may require manual reconciliation. Full local snapshots are automatically backed up in `foggybrain_sync_backups` before applying sync; no restore API or pruning is provided. Local layouts are preserved and cleaned of removed tasks. No background workspace sync runs.
